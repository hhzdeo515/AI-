  结束总结与下一步计划。摄像头抽帧实时分析、视频离线分析**后置到第二版**

### 架构核心思路
把"问答型"和"主动提醒型"统一成同一条 `event → orchestrator → agent → Reply` 事件流，
区别只在 Agent 内部有没有状态机。全项目只有 `Task` / `Reply` 两个数据结构。

### 踩坑记录
1. **清华 PyPI 镜像没有 `dashscope` 包**（`from versions: none`），官方源有。
   装依赖要用 `-i https://pypi.org/simple`。
2. **`importlib.util.find_spec` 在父包不存在时抛 `ModuleNotFoundError` 而非返回 None**，
   用它做"模块是否存在"判断必须 try/except。
3. **粘性场景规则会吞掉其它场景的输入**：会议进行中，`计算 (18+24)*3` 被当成会议内容。
   修正：路由顺序必须是 事件 → 显式场景 → **关键词** → **粘性** → LLM。
   会议 collecting / 建档 awaiting / 训练 active 三种粘性状态都适用同一顺序。
4. **浮点精度**：`120/(1+0.2)` 结果是 `99.99999999999999`，断言要带容差。
5. **器械名不适合堆进关键词表**：改由 `FitnessAgent.can_handle` 查 `equipment.find()` 判定（0.9 分）。
6. **PDF 中文不必带字体文件**：reportlab 内置 `UnicodeCIDFont("STSong-Light")` 即可，
   避免把 9.7MB 的 simhei.ttf 塞进仓库。docx 中文则需设 `w:eastAsia` 字体。
7. **Git Bash 的 `/tmp` 路径在 Windows Python 里不存在**，脚本里写文件要用项目内相对路径。
8. **Web 层验收用 Flask `test_client` 比起真服务再 curl 更可靠**（10 项测试 1 秒跑完，无需端口）。
9. **同一句话可能同时命中两个场景的关键词**：「导出刚才的纪要成 Word」同时含 meeting 的
   「纪要」和 resource 的「导出」。解法：让**更具体的意图拿更高置信度**
   （导出意图 0.95 > 普通关键词 0.8），而不是靠 Agent 注册顺序。
10. **错误分支别复用带硬编码字段的构造函数**：`_list` 的空分支复用了硬编码
    `action="export"` 的 `_need`，导致「我有哪些资料」被标成 export 动作。
    单测没覆盖到（只断言了 scene 和 status），是**端到端跑 CLI 才发现的**——
    教训：每个分支的 `action` 也要断言。
11. **多 Agent 项目里，"归档"这类横切约定必须逐个 Agent 核对**：meeting / fitness 都写了
    `state_delta["_archive"]`，只有 exam 没写，于是**题解静默地从不落库**。
    编排层只认 `_archive`，Agent 自己塞的 artifact 不会触发持久化——
    这类"看起来返回了、其实没存"的 bug 不跑真实链路根本发现不了。
12. **测试绝不能依赖"没有 API Key"**：`test_full_workout_session_via_events` 原来断言
    模型降级文本，配上 Key 后立刻变红。需要模型的路径一律**打桩**，
    并**单独写一条降级路径测试**。否则测试结果会随环境漂移。
13. **提示词要显式禁止"合理补全"**：模型会把"需李四确认"扩写成"需在 2 个工作日内确认"，
    并凭空生成"启动财务流程"行动项。光说"不要虚构"不够，
    要举反例说明（"原文只说 X，就不能写成 Y"）才有效。
14. **两个测试文件里的同名 helper 容易写混**：`test_workout.py`/`test_exam_tools.py` 用
    `_fresh_db()`，其它用 `_fresh()`。复制粘贴测试时踩了两次。
