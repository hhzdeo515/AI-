## assistant-lite：三场景轻量级 multi-agent 助手（P0–P2 完成）

### 背景与决策
在 `E:\AI智能助手\` 下新建 `assistant-lite\`，替代旧 `dify-assistant\`（Dify Chatflow + Docker，太重）。
面向三场景：**会议纪要 / 拍照解题 / 锻炼指导**。砍掉旧的导航场景。

用户拍板的关键决策：

- 模型：**阿里云百炼 OpenAI 兼容接口**（`dashscope.aliyuncs.com/compatible-mode/v1`），
  文本 `qwen-plus` / 视觉 `qwen-vl-max` / 语音 `qwen3-asr-flash`
- 交付：本地 CLI + 本地 Web 页（P5）

  结束总结与下一步计划。摄像头抽帧实时分析、视频离线分析**后置到第二版**
- 项目位置：新建目录；**git 仓库建在 `E:\AI智能助手\` 根目录**

### 架构核心思路
把"问答型"和"主动提醒型"统一成同一条 `event → orchestrator → agent → Reply` 事件流，
区别只在 Agent 内部有没有状态机。全项目只有 `Task` / `Reply` 两个数据结构。

### 关于「接到眼镜上还差什么」（用户提问后的核查结论）
- **ASR 已有**（`llm.asr` → qwen3-asr-flash），会议 agent 自动触发
- **OCR 刻意不做**：`llm.vision` 直接把图交给多模态模型。公考图形推理题做 OCR 会压平
  九宫格的行列/黑白/叠加关系，直接做废。初解与终审**各自重看原图**也是为此
- **旧版设计有 `display_text` + `speech_text` 两个字段**（`Dify智能助手搭建方案.md`），
  现在 `Reply` 只有一个 `text`。眼镜上不可能把 600 字纪要念出来 → **这是真缺口**
- 旧版还设计了 TTS、播报打断（"设备立即停止当前播放；使旧播放队列失效"）——都没有
- 本机**没装 ffmpeg**，长音频分片做不了（纯 wav 可用标准库切）

### 踩坑记录
1. **清华 PyPI 镜像没有 `dashscope` 包**（`from versions: none`），官方源有。
   装依赖要用 `-i https://pypi.org/simple`。
2. **`importlib.util.find_spec` 在父包不存在时抛 `ModuleNotFoundError` 而非返回 None**，
   用它做"模块是否存在"判断必须 try/except。
3. **粘性场景规则会吞掉其它场景的输入**：会议进行中，`计算 (18+24)*3` 被当成会议内容。
   修正：路由顺序必须是 事件 → 显式场景 → **关键词** → **粘性** → LLM。
   会议 collecting / 建档 awaiting / 训练 active 三种粘性状态都适用同一顺序。
4. **浮点精度**：`120/(1+0.2)` 结果是 `99.99999999999999`，断言要带容差。
5. **器械名不适合堆进关键词表**：改由 `FitnessAgent.can_handle` 查 `equipment.find()` 判定（0.9 分）。
6. **PDF 中文不必带字体文件**：reportlab 内置 `UnicodeCIDFont("STSong-Light")` 即可，
   避免把 9.7MB 的 simhei.ttf 塞进仓库。docx 中文则需设 `w:eastAsia` 字体。
7. **Git Bash 的 `/tmp` 路径在 Windows Python 里不存在**，脚本里写文件要用项目内相对路径。
8. **Web 层验收用 Flask `test_client` 比起真服务再 curl 更可靠**（10 项测试 1 秒跑完，无需端口）。
9. **同一句话可能同时命中两个场景的关键词**：「导出刚才的纪要成 Word」同时含 meeting 的
   「纪要」和 resource 的「导出」。解法：让**更具体的意图拿更高置信度**
   （导出意图 0.95 > 普通关键词 0.8），而不是靠 Agent 注册顺序。
10. **错误分支别复用带硬编码字段的构造函数**：`_list` 的空分支复用了硬编码
    `action="export"` 的 `_need`，导致「我有哪些资料」被标成 export 动作。
    单测没覆盖到（只断言了 scene 和 status），是**端到端跑 CLI 才发现的**——
    教训：每个分支的 `action` 也要断言。
11. **多 Agent 项目里，"归档"这类横切约定必须逐个 Agent 核对**：meeting / fitness 都写了
    `state_delta["_archive"]`，只有 exam 没写，于是**题解静默地从不落库**。
    编排层只认 `_archive`，Agent 自己塞的 artifact 不会触发持久化——
    这类"看起来返回了、其实没存"的 bug 不跑真实链路根本发现不了。
12. **测试绝不能依赖"没有 API Key"**：`test_full_workout_session_via_events` 原来断言
    模型降级文本，配上 Key 后立刻变红。需要模型的路径一律**打桩**，
    并**单独写一条降级路径测试**。否则测试结果会随环境漂移。
13. **提示词要显式禁止"合理补全"**：模型会把"需李四确认"扩写成"需在 2 个工作日内确认"，
    并凭空生成"启动财务流程"行动项。光说"不要虚构"不够，
    要举反例说明（"原文只说 X，就不能写成 Y"）才有效。
14. **两个测试文件里的同名 helper 容易写混**：`test_workout.py`/`test_exam_tools.py` 用
    `_fresh_db()`，其它用 `_fresh()`。复制粘贴测试时踩了两次。
15. **`[hidden]` 会被 CSS 的 `display:flex/inline-flex` 覆盖**：附件菜单、"End Session"、
    "Clear" 三个元素该隐藏却一直显示。必须显式写 `[hidden]{display:none!important}`，
    且要放在组件规则之前。
16. **SPA 视图切换必须监听 `hashchange` + `popstate`**：只用 `location.hash` 读初值、
    不监听变化的话，浏览器后退键失效；而且**同页改 hash 不会重载**，
    用 CDP/无头浏览器逐视图截图时全部拿到同一张图（我是靠对比 md5 发现的）。
17. **要"真实的进度动画"就得让后端上报进度**：前端假动画违背"每个动效都要有目的"。
    做法：`progress.py` 登记 request_id 的执行阶段，Agent 在关键步骤 `report()`，
    前端轮询 `/api/progress`。没有记录时返回空 steps，前端回退到"整体处理中"。
18. **Windows 上无法用 agent-browser 时的浏览器验证方案**（很好用，值得复用）：
    - headless Chrome 截图：**输出路径必须是纯英文**，中文路径下 Chrome 静默不写文件
    - 交互态验证：`--remote-debugging-port=9222` + Node 22 内置的 `WebSocket` 写个极简 CDP 客户端，
      可 `Page.navigate` / `Runtime.evaluate`（点击）/ `DOM.setFileInputFiles`（注入文件）/
      `Page.captureScreenshot` / `Emulation.setDeviceMetricsOverride`（断点）
    - **后台进程必须用 run_in_background 启动**：用 `&` 起的服务/Chrome 会随该条命令一起结束，
      后续 curl/截图拿到的是网络错误页
    - Git Bash 的 `/tmp` 在 Windows Python 里不存在，`curl -o /tmp/x` 会静默失败读到残留文件
19. **用 `innerHTML` 覆盖面板会摧毁后续需要的元素**：Fitness 的空闲态用 innerHTML 重写了整个
    Workout 面板，切到活跃态时 `#fit-sets` / `#fit-state` 已不存在 → `TypeError`。
    正确做法是**两种状态的 DOM 都放在页面里，只切换 `hidden`**，绝不重写 innerHTML。
20. **异步流程必须用 `try/finally` 释放锁**：上一条的 `TypeError` 从 `refreshState()` 抛出后，
    `runComposer` 的 `S.busy = false` 永远不会执行 → **发送按钮永久禁用，UI 锁死**。
    这类"一个渲染异常导致整个界面卡住"的 bug 只有真操作才暴露。
21. **前后端字段要对齐**：前端一直在提交 `event`（眼镜按键/语音事件的入口），
    但 `/api/chat` 只读 `text/scene`，整个字段被静默丢弃——事件驱动设计直接失效。
    前端发的每个字段都要在后端找到接收处。
22. **本地工具必须关掉静态资源缓存**（`SEND_FILE_MAX_AGE_DEFAULT = 0`），
    否则改了 `app.js` 用户还是拿旧版，排查时会严重误导（我就先误判成缓存问题，
    实际是另一个 bug，但缓存确实是真问题）。
23. **CDP/无头浏览器测试时，导航到完全相同的 URL 不会重载页面**。
    必须加时间戳参数（`/?t=Date.now()#view`），否则拿到的是上一次的 DOM，
    会看到"改了代码却没生效"的假象，并读到上一页残留的异常堆栈（行号对不上就是信号）。
