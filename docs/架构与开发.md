# 架构与开发

项目分为 Vercel Demo 与前后端完整版，详见 [Demo 与完整版](Demo与完整版.md)。`npm run dev:demo` / `build:demo` 使用浏览器示例数据；`npm run dev` / `build:full` 使用真实后端。下文描述完整版。

| 目录 | 职责 |
| --- | --- |
| frontend/scripts | 原版界面导出、本地静态服务与后端代理 |
| frontend/lib | Demo 示例数据与原版接口适配 |
| frontend/app、frontend/components、frontend/hooks | 历史 Next.js 源码，当前首页和发布构建不使用 |
| langgraph-app/lg_assistant/web | Flask API、鉴权、静态前端、受保护素材 |
| langgraph-app/lg_assistant/jobs.py | 持久任务、有限工作线程、会话串行、中断恢复 |
| langgraph-app/lg_assistant/*graph.py | LangGraph 主图与业务子图 |
| deploy | 在线检查、备份、托管配置 |

首页使用 Flask 的原版模板与 JavaScript，包含镜片布局和 3D 戒指。Flask 管理业务和鉴权，LangGraph 管理 AI 流程。前端访问同源 /api，模型密钥只在后端。完整版运行时只有一个 Python 进程，/ 与 /legacy 都显示原版界面；Vercel Demo 从同一套模板与静态资源导出。

## 本地开发

需要 Python 3.11、Node.js 24。先在 langgraph-app 安装 requirements-dev.txt 和 requirements-production.txt，首次复制 .env.example 为 .env 并填写模型配置。离线测试不需要模型凭据。

在两个终端分别运行：

```powershell
# 终端一
cd langgraph-app
python run.py web --port 5000
# 终端二
cd frontend
npm ci
npm run dev
```

打开前端服务打印的地址。API_PROXY_TARGET 默认 http://127.0.0.1:5000，只填后端地址。

构建后同源运行：

```powershell
cd frontend
npm run build
cd ../langgraph-app
$env:FRONTEND_DIR = (Resolve-Path ../frontend/out).Path
python run.py web --port 8802
```

首页与登录页始终使用原版 Flask 模板；FRONTEND_DIR 仅供导出资源兼容使用，不会让历史 Next.js 页面覆盖入口。

## 任务生命周期

POST /api/chat/async 保存输入并返回 task_id，浏览器轮询同一任务，刷新/断网后不会重新提交。

- pending：入库排队；重启后可以继续。
- running：执行中；实际进度随步骤持久化。
- done：已有结果；还需检查业务结果是否要求补拍、选择题型或是否失败。
- error：执行异常，可以显式重试。
- interrupted：重启中断或外部结果不确定，等待用户继续，后台不盲目重复提交外部任务。

重试复用同一请求、回执及匹配检查点。原会话已被新请求推进时，不把旧任务写入新的上下文。
当前是全局口令，owner 是资料分组，并非多租户账号授权。

## 验证

```powershell
cd frontend
npm test
npm run typecheck
npm run build
cd ../langgraph-app
python -m pytest tests -q
Get-ChildItem tests/test_*.cjs | ForEach-Object {
    node $_.FullName
    if ($LASTEXITCODE -ne 0) { throw "前端兼容测试失败" }
}
```

GitHub Actions 运行上述检查。真实模型与真实设备验收需使用明确选择的测试素材；离线通过不能代表模型准确率。
