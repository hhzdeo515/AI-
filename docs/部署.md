# Demo 与完整应用部署

当前 Vercel 站点发布原版界面 Demo、独立翻译函数、高德接入与 IMU 模拟，使用 `frontend/vercel.json` 中的 `npm run build:demo`，无需 Python 后端或模型密钥。实时翻译使用真实在线服务；手动 IMU 已可用，高德底图仍需开发者配置。题解和会议的浏览器示例数据不承担真实业务持久化。启动、限制和验证见 [Demo 与完整版](Demo与完整版.md)。下文适用于真实后端完整版。

Vercel 翻译函数使用私密 `TRANSLATION_ACCESS_TOKEN`；高德使用私密 `AMAP_JS_API_KEY` 与 `AMAP_SECURITY_JS_CODE`。安全密钥不返回浏览器，由同源代理追加。未配置高德时 `/api/map-config` 应返回 503，方向模拟仍可用；配置齐全后必须验证实际底图、地点搜索、GPS 坐标转换、代理鉴权与方向同步。

当前恢复为 **原版 HTML / JavaScript 界面 + Flask / LangGraph 后端**。完整应用必须在用户电脑关机后仍能使用，并采用固定 HTTPS 地址与访问口令。推送源码、构建通过、本机预览均不代表上线。

## 一个常驻容器（默认）

根目录 Dockerfile 导出原版界面资源，再把 frontend/out 放进 Python 镜像。Flask 直接提供原版首页、登录、静态资源和 API，运行时只有一个常驻 Python 进程。

必须单实例、单进程，挂载 /var/lib/ai-assistant 持久卷。卷内保存业务库、任务、检查点、素材和导出文件。生产入口锁定数据目录，拒绝另一实例使用同一卷。电脑上的已有记录不会自动上传。

```sh
git clone https://github.com/hhzdeo515/AI-.git
cd AI-
cp deploy.env.example deploy.env
# 填入模型凭据和至少 24 字符的随机 ACCESS_TOKEN。
docker compose up -d --build
docker compose ps
```

Compose 仅监听服务器 127.0.0.1:8804；通过 HTTPS 反向代理访问。代理请求体限制至少 32 MB。容器端口由 PORT 指定，默认 10000。

- Render 模板：根目录 render.yaml，Docker、单实例、持久磁盘、/health。涉及付费资源，需账号持有人确认费用。模板关闭自动部署，以便发布前等待任务结束。
- Railway：根目录 Dockerfile、一个副本、相同挂载目录。镜像 UID=10001，卷必须允许写入，或按平台要求配置运行用户。
- 私密环境变量：ACCESS_TOKEN、DASHSCOPE_API_KEY，可选 TYPESAFE_API_KEY。不要上传 deploy.env。
- PUBLIC_SCHEME=https；TASK_WORKERS 默认为 2，范围 1–16，是单进程内工作线程数。

### Render 首次部署

1. 打开[本仓库的 Render 部署入口](https://render.com/deploy?repo=https%3A%2F%2Fgithub.com%2Fhhzdeo515%2FAI-)，登录自己的 Render 账号。
2. 确认仓库 hhzdeo515/AI-、分支 master，以及付费实例和 5 GB 持久磁盘。模板使用 0.5c-512mb，基础计算费 7 美元/月、磁盘 1.25 美元/月；不含模型调用和超额用量，以[当前价格](https://render.com/pricing)为准。若任务规模增大，需根据内存监测升级实例。
3. 在私密环境变量输入 DASHSCOPE_API_KEY。ACCESS_TOKEN 由 Render 自动生成，不填入源码。默认只开原版流程；需要 JEV 时再在服务环境中添加 TYPESAFE_API_KEY。
4. 确认创建后等待服务 Live。平台会提供固定 HTTPS 地址。先确认 /health 返回 ok=true、auth_enabled=true；未登录访问 /api/resources 应返回 401。
5. 账号持有人在 Render 的服务 Environment 中查看 ACCESS_TOKEN，用作助手的登录口令；不要将口令或模型密钥发送到聊天或写入日志。
6. 按下一节将后端 HTTPS 地址接入 Vercel。后续发布仍先确认活动任务结束，不开启无条件自动重启。

该小内存模板将 TASK_WORKERS 设为 1，仍支持持久排队；优雅关闭最长等待 300 秒。不要选择无持久磁盘的免费实例替代，以免重启丢失记录。

## 独立 Vercel 完整版前端 + 云端后端

| Vercel 设置 | 值 |
| --- | --- |
| Application Preset | Other |
| Root Directory | frontend |
| Install Command | npm ci |
| Build Command | npm run build:full |
| Output Directory | out |
| Production Branch | master |

为保留现有 Demo，应使用独立 Vercel 项目与部署分支，勿覆盖 master 的 Demo 配置。先部署常驻云端 Python 后端，再在该分支把 deploy/vercel.frontend.example.json 复制到 frontend/vercel.json，将所有 YOUR-CLOUD-BACKEND.example 替换成实际后端 HTTPS 域名并提交。该配置把 /api、/health 和兼容页面代理到后端，浏览器使用同源 HttpOnly Cookie。需验证实际代理后的上传大小和响应时间。

Vercel 不需要模型密钥，口令也只配置在 Python 后端。后端不能是 localhost、用户电脑或临时隧道。完整前端配置将首页、登录、业务 API 和静态资源代理到原版 Flask。构建需允许读取根目录以外的源码。首次配置完成后，生产分支提交可触发前端自动部署；后端更新仍需等任务结束后发布。

当前后端仍需要常驻线程和持久磁盘，不能当作 Vercel Flask Function 部署。若以后全部迁入函数平台，还需要共享数据库、对象存储和持久任务执行服务。

官方依据：[静态导出](https://nextjs.org/docs/app/guides/static-exports)、[外部重写](https://vercel.com/docs/routing/rewrites)、[Render 配置](https://render.com/docs/blueprint-spec)。

## 更新、备份与上线检查

1. 完成检查并构建镜像。
2. 确认实际 /health 的 active_tasks=0，并暂停用户提交后更新。
3. 停止应用，备份持久数据。backup_data.py 不修改原数据、不覆盖已有备份，输出必须在数据目录之外；备份含私人数据，应私密保存。
4. 新镜像挂载原数据卷启动；不要运行 docker compose down -v。
5. 验证实际 HTTPS 地址，再用明确选择的素材检查模型业务。

```sh
# 口令在私密 ACCESS_TOKEN 环境变量中，不作为命令参数。
python deploy/check_online.py --url https://你的实际域名 --wait-idle 300
# 在应用停止、能访问持久数据的环境中：
python deploy/backup_data.py --data-dir /var/lib/ai-assistant --output /private-backups/assistant-20261003.tar.gz
```

线上检查覆盖原版登录、眼镜与戒指页面和静态资源、health、Cookie、业务/任务接口鉴权及退出，不调用收费模型、不上传用户资料。浏览器还需确认实际镜片、戒指、拍照/录音、逐题阅读、刷新后的任务和结果恢复。

回滚时切回旧镜像并保留持久卷；新增任务表不删除原表。强制停止留下 interrupted 任务，用户可显式继续，不会显示为成功。/legacy 保留原界面。
