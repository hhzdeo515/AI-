# 完整应用部署

本应用需要常驻 Python 服务、后台任务线程和持久磁盘。使用单进程、单实例部署；数据卷同时保存 SQLite 数据库、LangGraph 检查点、上传素材和导出文件。已有电脑上的用户记录不自动上传。

## 云服务器或持续运行的容器平台

仓库根目录的 `Dockerfile` 构建包含 ffmpeg 的 Linux 镜像，由非 root 用户运行。生产入口为 `langgraph-app/production.py`，使用 Waitress 单进程服务器。

服务器上需要 Docker 和 Docker Compose。首次配置：

```sh
git clone https://github.com/hhzdeo515/AI-.git
cd AI-
cp deploy.env.example deploy.env
# 编辑 deploy.env，填写模型凭据及至少 24 字符的随机 ACCESS_TOKEN。
docker compose up -d --build
docker compose ps
curl http://127.0.0.1:8804/health
```

生产入口会拒绝未设置或过短的访问口令。健康接口不需要口令，其余页面与业务接口受口令保护；登录 Cookie 在生产环境设置为 Secure 和 HttpOnly。

Compose 默认仅在服务器的 `127.0.0.1:8804` 监听。用服务器上的 HTTPS 反向代理将域名转发到此地址；域名与证书需要在选定服务器上配置。平台若直接提供 HTTPS 域名，则将容器端口设置为 `10000`（或通过 `PORT` 指定），并挂载 `/var/lib/ai-assistant` 持久目录。

反向代理的请求体限制至少设为 `32 MB`，以支持应用允许的图片、录音和资料上传。

## 托管平台配置

选择支持持续运行容器和持久磁盘的平台，例如 Render 或 Railway。连接此 GitHub 仓库后，设置：

- 构建方式：仓库根目录 `Dockerfile`。
- 健康检查：`/health`。
- 单实例，持久磁盘挂载到 `/var/lib/ai-assistant`。
- 环境变量：`deploy.env.example` 中的模型配置，及随机 `ACCESS_TOKEN`。
- 自动部署：选择本仓库 `master` 分支的新提交。

模型凭据保存在平台的私密环境变量中。Render 的持久磁盘需要付费服务；实际平台、套餐与域名在账号接入后确定。平台默认临时文件系统无法替代持久磁盘。

Railway 的卷由 root 挂载；本镜像默认以 UID `10001` 运行。若使用 Railway 并遇到卷写入权限限制，需要按平台要求设置 `RAILWAY_RUN_UID=0`，或先为卷配置 UID `10001` 的写入权限。镜像构建阶段的 `chown` 不会改变后来挂载的磁盘权限。普通 Docker Compose 命名卷会从镜像初始化目录所有权。

## 更新与验证

更新服务器版本：

```sh
git pull --ff-only
docker compose up -d --build
```

挂载的数据卷在更新时保留。部署前应等待 `/health` 的 `active_tasks` 为 `0`，否则重启会中断正在处理的任务。不要运行 `docker compose down -v`，该命令会删除数据卷。

每次发布后检查：HTTPS 地址可打开登录页；正确口令登录后显示镜片和戒指；`/health` 返回 `ok=true`、`auth_enabled=true`；静态资源返回成功；未登录请求 `/api/resources` 返回 `401`。模型业务验证应使用显式选择的测试素材，不能用页面显示正常替代真实模型验证。

仅发布源码、README 或静态页面，无法承载本应用的完整后端。GitHub Pages 和普通无状态函数部署不满足当前存储及后台任务要求。
