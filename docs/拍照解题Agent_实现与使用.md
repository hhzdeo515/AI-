# 拍照解题 Agent：实现与使用

本次实现面向国央企与事业单位招聘笔试、单位内部考试、高校课程测试。运行入口是 `langgraph-app` 的眼镜视野中「拍照解题」场景；支持摄像头拍摄或导入照片，眼镜实物采集仍待设备端接入。

## 使用

1. 选择考试场景，必要时填写考试年份、教材或制度版本。
2. 照片可以包含多道题，保留题干、全部选项、共用材料与图形边缘；系统先清点可见题目，再逐题处理。完整题继续解答，残缺题单独提醒补拍。
3. 内部制度题先展开「参考资料」，添加资料标题、版本和正文，也可导入 UTF-8 TXT、Markdown、DOCX。文件最多 2 MB，正文最多 20 万字；Word 提取正文段落与表格，不识别嵌入图片、公式图片或扫描件。PDF 暂不直接导入，可粘贴所需原文。
4. 勾选要使用的资料，最多 20 份。选中资料后只在这些资料中检索，关闭公开联网检索。相关原文片段会发送给当前配置的模型服务；不是完全离线推理。
5. 结果直接显示在当前拍照页面，每道题上面是答案，下面是解析、真实计算结果及原文引用；长解析在同一页面内滚动阅读。资料缺失、引用无效或纠错后仍有矛盾时，显示具体补充要求。

资料正文可在列表中展开查看；删除资料会删除本地检索索引，但不会抹去已归档题解里的引用。资料存储持久化，页面本轮勾选和考试设置不跨刷新保留。

## LangGraph 结构

主图将编译后的批量图注册为 `exam_vision` / `exam_jev` 子图；兼容函数 `nodes.exam_vision()` 按模式调用同一批量入口。`exam_batch.py` 负责整批清点、原图分题与逐题结果，原版和 JEV 各自的 `EXAM_GRAPH` 保留为单题求解内核。

批量执行顺序：输入检查 → 清点所有可见题及共用材料 → 按原始像素裁出每题 → 完整题运行独立单题图 / 残缺题直接提示补拍 → 按照片阅读顺序汇总答案和解析。

执行顺序：输入检查 → 识题与像素读取 → 题型路由 → 按需取证 → 解答 → 程序校验 → 推理题独立解答 → 回看原图复核 → 输出归档。

- `perception_agent`：读取原图，记录题干、选项、表格、图形与缺失信息。
- `route_specialist`：根据题面和用户选定场景做确定性分流，不额外调用模型。
- `knowledge_agent`：优先检索所选本地资料；普通公开题默认按题型检索内置考试知识与方法。时效事实、命中的法律版本摘要进一步按题干年份联网核实。内部场景一律不向搜索服务发送题目。
- `solve_quantitative`：数量关系、资料分析和课程计算题。
- `solve_reasoning`：逻辑、图形、定义、类比与空间推理。
- `solve_knowledge`：内部制度、专业知识、课程资料题。
- `solve_general`：言语、阅读和未落入前述分工的综合题。
- `tool_verifier`：安全 AST 数字算式校验与黑白格逐位校验，不调用模型；支持一个操作数旋转或镜像后叠加。不适用的图形类别不能因矩阵工具拒绝而被视为无解。
- `independent_reasoning`：推理题使用第二个模型独立读取原图，不接收初解或文字转述；可使用同一原图的确定性像素观察。调用失败单独留痕，不能伪称已完成独立校验。
- `review_agent`：单独调用模型，再看原图，核验选项、公式、资料年份和引用。

每道题只走一个主解答分支；推理题另有独立检查。默认主模型 `qwen3.8-flash`，独立模型 `qwen3.7-plus`，图片解题开启思考、预算4096。曲线等定量图表读数、主解与独立解答的有效选项不同、或进入第二次纠错时，复核使用 `qwen3.8-max-0902`。可用 `EXAM_MODEL/EXAM_INDEPENDENT_MODEL/EXAM_REVIEW_MODEL/EXAM_THINKING_BUDGET` 覆盖，会议和通用聊天保持原配置。终审比较证据与具体反例，不按模型数量投票。

## 有限纠错

复核必须提出具体的计算、抄录或选项对应错误，才走 `repair → 原解答分支 → 程序校验 → 复核`。修复最多一次；普通题正常三次模型调用，推理题增加一次独立解答。JSON 格式重试和模型 SDK 的网络重试独立计算。已在终审中解决的问题写入核对记录，不应继续作为未解决问题触发纠错。

程序算式失败、黑白格输入格式错误不能被模型一句「核验通过」覆盖。第二次仍有问题时保留不可确定状态。缺图、模糊、资料缺失、规律不唯一不触发猜测循环；证据检索未取得来源时在解答前返回补充要求。

复核可给出与旧表达式精确对应、含原图依据的算式修正，程序重算成功后才替换原记录，保留旧表达式与修正原因。无关公式、常数或仍不可计算的修正不能覆盖原错误。模型输出格式异常和暂时连接错误共用一次有限重试预算，鉴权或其他无关配置错误不重试；不保证所有模型或网络故障都能恢复。

## 知识库与数据库

2026-09-30接入内置考试知识：30个模块、248条摘要与方法，共14204字。包括图形30条、类比26条、逻辑、定义、言语、数量、资料、申论、公基哲学、政治核验、法律、经济、管理、公文、历史、地理、科技，以及金融财会、计算机、教育、医疗和英语基础。覆盖主要公共科目和岗位基础，不宣称穷尽所有地区、专业和动态知识。

页面默认开启「考试知识与方法」，「查看内置考试知识」可按模块展开全部248条摘要正文、来源和版本说明。直接调用接口或解题图也默认启用公共知识；显式关闭、内部考试或指定私人资料时遵守相应范围。启动服务与直接调用解题图都会自动安装知识索引，更新内容按哈希同步；不需要人工导入。查询按题型、具体主题和别名筛选，最多提供4条，避免把全库塞进提示词。源码位于 `langgraph-app/lg_assistant/knowledge/`；构建器只整理概念，不读取题目、选项、标准答案或评分规则。

来源分两类：`scope`仅界定官方考试范围，解题方法为独立整理，不冒称官方原文；`authority`为有来源、有版本说明的概念摘要。法律、公文规范标为版本相关，须按考试时间核实；旧法不能用作任意年份的现行依据。没有用户资料的公共概念是辅助知识，引用缺失不阻止自足的数学或逻辑题，但伪造引用不会展示。所选用户资料仍要求有效逐字引用。

复用 `data/app.sqlite3`，新增 `exam_documents`、`exam_chunks` 与 FTS5 索引 `exam_fts`；不新增向量服务或独立数据库进程。

中文按相邻双字建索引，英文按词建索引；正文每 800 字建立最多 1000 字片段。选定资料内 BM25 检索，最多提供 4 个相关片段。标题、版本、原文、摘要哈希和创建时间持久化。相同用户的相同标题、版本与内容重复导入复用原记录。

引用必须给出有效片段 ID 和该片段中真实存在的逐字原文；程序校验引用存在性，模型负责判断原文能否支持结论。这个检查不能证明模型对资料语义的理解一定正确。

现有 LangGraph 检查点保存执行状态，现有资源表归档题解，已有请求回执保持幂等。每轮重新初始化子图私有状态，避免上一题的引用、纠错次数或答案串入新题。

`owner` 用于本地数据分组隔离，沿用项目的全局访问口令；它不是企业级多租户授权系统。未建设单位账号、角色权限或共享知识库。

## 接口

- `GET /api/exam/knowledge?owner=local`：列出资料元信息。
- `GET /api/exam/public-knowledge`：内置考试知识目录、来源与版本限制，不包含用户私人资料。
- `POST /api/exam/knowledge`：JSON `owner/title/version/content`，或同名 multipart 字段加 `file`。
- `GET /api/exam/knowledge/<id>?owner=local`：查看原文。
- `DELETE /api/exam/knowledge/<id>?owner=local`：删除资料与索引。
- 原有 `POST /api/chat`、`POST /api/chat/async` 支持在 `event.exam` 中传入：

```json
{
  "profile": "internal",
  "exam_date": "2025版制度",
  "document_ids": ["导入返回的32位id"],
  "require_knowledge": true,
  "allow_web": false
}
```

`profile` 支持 `auto/recruitment/internal/campus`。主图保持拍照与上一图追问路径；无图片的新文本请求仍使用原有文本助手，当前新增资料取证子图以图片请求为入口。

响应沿用正文与 `artifacts`，其中视觉 artifact 增加 `specialist`、`repair_count`、`trace`、`reference_ids`。`trace` 记录真实节点耗时和错误状态，可用于定位模型或检索瓶颈。多题响应另含 `kind:exam_batch`，提供总题数、已答数、补拍数、失败/待核验数、整批原图复用标记，以及每题的页码、区域、状态、答案、解析和补充要求。单题视觉 artifact 附 `question_id/question_label`，便于对应每道题。

## 拍照入口补充

网页以「拍照」为主要入口，优先请求后置摄像头，照片先放入输入框确认后发送，文字为可选补充。也支持相册和截图粘贴。拍照静音默认开启并保存在浏览器本地，控制应用内提示音；不能控制系统相机快门声。应用拍照仅请求视频，不请求麦克风。关闭取景窗口或切到后台会释放摄像头。

## 2026-09-30多题识别与当前页面显示

批量入口不设置固定题数上限，支持多列、多张照片、同页共用材料和确认连续的跨页题。题号重复不会删除题目；同号题的下载正文与播报附照片序号。EXIF方向归正后从原始像素裁图，材料、表头、单位与图形随需要引用到每题。上轮追问保留全部原照片，不保留已删除的临时裁图。

残缺或模糊题保留在清单中，指出页码、题号和需要补拍的区域；不进入求解。清点结构无效或区域无效也要求补拍，避免将异常字段当成完整题。完整题分别运行单题图，一题失败不会取消其他题；每题使用新的执行上下文，避免并发检查点、引用、答案及重试状态串题。真实模型调用和耗时汇总回根请求。

默认同时处理3题，可用 `EXAM_BATCH_WORKERS=1..8` 调整并发；这只控制同时处理数，不限制整批题数。异步页面一直轮询同一个任务，不在长任务超时后自动重复提交；进度显示实际已处理数。每题答案在上、解析在下，在拍照页面的正常布局中阅读，原照片同屏保留。

已通过真实网页接口验证：混合照片清点3题、答对2道完整题、底部第3题被截断的B/C/D选项提示补拍（原版与JEV均通过）；共用销售额表格2题均答对；双栏6题全部识别并答对。标准答案仅用于收到响应后的比较，没有传入模型或知识库。结果保存在 `outputs/exam-batch-20260930/`，可复跑：

```powershell
cd langgraph-app
python scripts/validate_exam_batch_live.py --case mixed --live --backend original
# 共用材料：--case shared；双栏：--case many；另一模式：--backend jev
```

这些是可控图片的功能验证，不能代替真实手机照片准确率评测。当前清点模型对合法输出中的漏列、误合并仍可能漏检；原图长边2048缩放可能影响密集小字，照片外完全没有拍到的题无法计数。支持逐题处理与补拍提醒，不宣称任意模糊、遮挡或高密照片都必然无漏题。此前准确率评测使用单题内核，多题端到端识题率与每类90%仍需独立真实留出集验收。

本轮最终离线检查在禁止网络连接下通过373项测试及116项子检查；9个前端测试文件和两个脚本语法检查通过。批量回归包括12题不截断、错误缺失字段保留补拍要求、逐题失败隔离、共用材料原像素裁图、跨页重复题号、EXIF方向、临时文件清理、全部原图复用、并发执行上下文隔离和真实调用指标合并。实际浏览器验证每题答案在解析之前、结果使用正常布局、长正文独立滚动且照片同屏。服务已加载批量入口；本轮汇总为 `outputs/exam-batch-20260930/report.json`。

## 镜片内切换拍到的题目

多题照片解答后，镜片上方显示「上一题」「题号选择」「下一题」和当前位置，默认查看第一题。每次切换同步显示该题局部题面、答案和解析；共用材料与题区分别裁出并拼接，保留原始照片供后续处理。残缺、失败或待核验题也在选择列表中。单题和未识别到题目时隐藏切题控件，第一题与最后一题禁用相应方向。

切换使用已生成的结果。每题分别记住解析滚动位置，返回操作后查看上次答案也保留选题与位置；导入新照片则初始化。播报当前题，下载保留全批结果。当前镜片采集一次持有一张照片，局部题面仅使用该照片页码的有效坐标；没有有效题区时展示完整原照片。裁图使用已解码图片同步生成，切换期间不会发生旧异步裁图覆盖新题面的问题。

已通过逐题导航、残缺题选择、统计、滚动恢复、播报、新照片复位，以及11项题区/共用材料/跨页/坐标/尺寸/缓存/绘图失败回退检查。实际网页流程导入三题图后，已验证下一题和题号跳转同步更新题面与题解，整批统计保持3题。截图与验证记录保存在 `outputs/exam-batch-20260930/question-switch*`。

## 清晰图形题拒答与误报补拍的修正

用户反馈的三视图照片中，原 JEV 请求在识别和两次求解完成后选择停止作答，没有进入最终发布核验。原程序却对所有选答未通过的情况使用同一句“放大图形并重新拍摄”，不能据此认定原图模糊。再次诊断确认，初次识别与解答中的选项占格、投影和遮挡描述存在矛盾。另一次真实网页复测把完整可见的右侧选项错误描述成全部被裁切。

现在选答未通过时使用 `reasoning_unresolved`；真实缺失、资料不足、复核冲突使用不同原因字段。批量状态优先读原因字段，推理和服务失败不会因提示文字里出现“模糊/补拍”就被归为照片残缺。镜片对应显示未确定原因、处理失败或补拍提示。

清点中被判残缺的题先整批进行一次独立原图检查，只更新原题完整性和经过校验的题区，不删除题目或改变顺序。二次检查可以纠正误报，也可保留确实被截断的题；格式或服务失败时保留已有记录。题号或选项标签局部截边不等于必要选项内容缺失。完整且排列明确的选项可使用位置索引，JEV最终显示第几个选项，不冒称识别出不可见的字母。

完整图形题在 JEV 初次拒答后增加一次强模型原图复核，重新记录选项占格、投影方向和内部可见边，随后仍由 JEV 重选并核验发布；不以模型票数或复核模型身份强行给答案。单次强复核最多等待120秒或用户配置的更长时间，普通调用的超时和不叠加网络重试策略保持原有契约。这个补救可能增加复杂题的等待时间。

诊断照片、初解全状态、超时与强复核结果保存在 `outputs/user-projection-20260930/`。强复核曾纠正占格记录但仍给出不一致的柱体解释，JEV继续拒答。这证明误导提示可以修正，并不证明三视图已经达到90%正确率。没有把本题答案写进提示词或知识库。

## 连续拍照时重新采集题目

镜片将刚拍摄或导入、尚未提交的图片标记为待解答。首次处理后，无论成功或失败，再选「拍照解题」都会打开摄像头采集新照片；只有明确选择「重新解答当前图片」才再次提交保留的旧图片。新导入的图片仍可直接开始解答。摄像头打开时隐藏旧照片，收起后保留上次答案、选题及阅读位置。

11个前端测试文件及脚本语法检查通过，覆盖成功和失败后的再次拍照、两次拍摄使用不同的新照片、重复点击防护，以及取消后迟到的图片生成/解码不覆盖旧结果。实际网页导入测试题并完成解答后，再点「拍照解题」已打开实时摄像头；未拍摄新照片，收起后仍能查看原答案。截图保存在 `outputs/camera-repeat-20260930/repeat-photo-menu.jpg`。
